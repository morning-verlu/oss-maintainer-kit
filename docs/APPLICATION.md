# Codex for Open Source Application Pack

This document prepares honest application text for the Codex for Open Source form.

## Reality Check

Starting a new project now is allowed if you are the owner and maintainer, but it is less competitive than applying with an already adopted OSS project. The program says it looks at repository usage, ecosystem importance, active maintenance, role, and permissions. Do not claim stars, downloads, or maintainer status that are not true.

Best next step: publish this repository publicly, tag `v0.1.0`, add a short demo, invite real users to try it, and apply only with accurate current metrics.

Published repository: https://github.com/morning-verlu/oss-maintainer-kit

Initial release: https://github.com/morning-verlu/oss-maintainer-kit/releases/tag/v0.1.0

## Suggested Form Answers

### Role

主要维护者

Use this only if the repository is created under your GitHub account or an organization where you control the project.

### Why This Repository Qualifies

Chinese draft, under 500 characters:

```text
oss-maintainer-kit 是我维护的公开开源项目，面向 OSS 维护者的高频工作流：issue triage、PR diff review、release notes。项目提供 CLI/GitHub Action、离线 fallback、测试与安全政策。它目前是新项目，暂无大规模使用量；申请理由是它直接服务维护者自动化，可帮助小型开源项目降低评审和发布负担。
```

English draft:

```text
oss-maintainer-kit is a public OSS project I maintain for common maintainer workflows: issue triage, PR diff review, and release notes. It provides a CLI, GitHub Action, offline fallback, tests, and security policy. It is a new project without large adoption yet; the reason to consider it is that it directly improves maintainer automation for small OSS projects.
```

### API Credits Use

Chinese draft, under 500 characters:

```text
API 额度将用于在该项目中运行 Responses API 驱动的 PR 审查、issue 分类、发布说明生成和维护策略建议；优先用于开源仓库 CI/Action 的真实维护任务，限制在本人拥有或获授权的仓库，避免处理私密安全报告，保留人工最终审核。
```

English draft:

```text
API credits will power Responses API workflows for PR review, issue classification, release-note drafting, and maintainer policy suggestions. Usage will focus on real OSS CI/Action maintenance tasks in repositories I own or am authorized to administer. Human maintainers remain the final reviewers.
```

### Anything Else

Chinese draft:

```text
我是该新仓库的创建者/主要维护者。项目仍在早期，申请不会声称已有星标或下载量；我会公开维护路线图、发布记录和安全政策，并持续收集真实使用反馈。
```

English draft:

```text
I am the creator and primary maintainer of this new repository. I will not claim adoption metrics the project does not yet have. I will keep the roadmap, releases, security policy, and real usage feedback public.
```

## Before Submitting

- Public GitHub repository URL.
- Public GitHub profile.
- ChatGPT account email.
- OpenAI organization ID from the API dashboard.
- Current stars, npm downloads, or real usage notes.
- A tagged release, preferably `v0.1.0`.
- A short demo issue or pull request showing the tool output.

## Higher-Probability Alternative

If you already contribute to an established OSS project, a stronger application is to become a documented core maintainer there and apply with that repository. Evidence can include merged PRs, issue triage, release work, write access, maintainer listing, or a note from the owner.
